# МячМяч — правовые документы

Статический сайт для GitHub Pages: обычный HTML, один CSS, системные шрифты.
Нет JavaScript, внешних ресурсов, аналитики и трекеров. Светлая и тёмная темы
выбираются через `prefers-color-scheme`. Ширина текста — до 760 px.

## Файлы

- `index.html` — общий каталог RU/EN с переключением между языковыми секциями.
- `privacy/index.html`, `en/privacy/index.html` — Политика RU/EN.
- `terms/index.html`, `en/terms/index.html` — Соглашение RU/EN.
- `404.html` — двуязычная страница ошибки.
- `style.css` — все стили, включая мобильную и печатную версии.
- `.nojekyll` — публикация готовых файлов без Jekyll.
- `content/*.md` — четыре локальные копии документов без редакторских замечаний.
- `build.py` — воспроизводимая генерация HTML и списка полей (Python 3.9+, stdlib).
- `verify.py` — локальная проверка HTML, ссылок, текста, структуры, полей и SLA.
- `PLACEHOLDERS.md` — полный дословный список оставшихся 28 полей.

## Редактирование и сборка

Заполните поля в `content/*.md`, синхронно в RU и EN. Затем:

```sh
python3 build.py --updated 2026-10-29
python3 verify.py
```

`--updated` — фактическая дата редакции сайта, не дата вступления документов
в силу. Поле `[ДАТА ВСТУПЛЕНИЯ В СИЛУ]` оставлено отдельно и не заполнено.

Первичные источники: `../ios-app-prepared/docs/appstore-audit/legal/`:
`privacy-policy.ru.md`, `privacy-policy.en.md`, `terms.ru.md`, `terms.en.md`.
Их `README.md` использован как редакторский контекст, но не опубликован как правовой документ.
Для повторного импорта после изменения первичных источников:

```sh
python3 build.py --source-dir ../ios-app-prepared/docs/appstore-audit/legal --updated 2026-10-29
python3 verify.py
```

Импорт заменяет `content/*.md`, поэтому сначала перенесите туда актуальные
заполненные сведения. Сборка без `--source-dir` независима от iOS-репозитория.
Поддерживаемое подмножество Markdown: заголовки, абзацы, плоские нумерованные и
маркированные списки, таблицы, жирный текст и код. Новые виды разметки требуют
расширения конвертера. Текст HTML экранируется; скобочные поля не становятся ссылками.

## Удалённые редакторские заметки

Только при импорте в сайт (не из первичных источников) удалены:

- блоки `[ПРОЕКТ: …]` и английское `Draft: …` — инструкции заполнить поля и обратиться к юристу;
- блоки `[ПЕРЕД ПУБЛИКАЦИЕЙ: …]` и `Before publication: …` — предупреждения о проверке реализации удаления аккаунта;
- заключительная редакторская фраза раздела 11 Политики о необходимости раскрыть серверный ИИ в разделе 8, на обоих языках.

Все содержательные поля, включая длинные `[ПОДТВЕРДИТЬ …]`, правовые основания,
сроки хранения/удаления и порядок ответа на запросы о данных, оставлены дословно.
Последние — не SLA обработки жалоб и не заменены на 24 часа. Сайт не является
подтверждением юридической или технической готовности приложения.

## Согласованные сроки — 2026-10-29

Фото проверяются модераторами **до публикации в течение 24 часов после загрузки**.
Жалобы на пользователей и контент рассматриваются **в течение 24 часов после получения**.
Это решение пользователя; фактическое исполнение сервером здесь не проверялось.
Условия отражены во всех четырёх первичных Markdown-файлах и на сайте.
Юридический email `[EMAIL ДЛЯ ОБРАЩЕНИЙ]` не подменяется адресом поддержки
`hello@ballball.ru`.

## Локальный просмотр и GitHub Pages

```sh
python3 -m http.server 8000
# Открыть http://localhost:8000/
```

Главные страницы используют относительные ссылки и работают как в корне домена,
так и в `/myachmyach-legal/`. У `404.html` задан `<base href="/myachmyach-legal/">`,
чтобы оформление и ссылки работали даже для неизвестных вложенных адресов на Pages.
Если репозиторий будет называться иначе или используется корень собственного домена,
пересоберите с правильным путём, например `--base-path /`.
Для локального просмотра 404 в текущей конфигурации обслуживайте родительский каталог
и открывайте `/myachmyach-legal/404.html`.

Для будущей публикации выберите GitHub Pages → Deploy from a branch → `main`,
`/(root)`. Для этого не нужна отдельная сборка GitHub Actions.
Публикация, создание remote и push в рамках этой задачи не выполняются.
